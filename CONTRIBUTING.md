# Contributing to CampusKit

Thank you for helping improve CampusKit. Contributions can include UX research notes, accessibility reviews, copy improvements, translations, visual design, documentation, and code.

## Before you start

- Check existing issues and open a new one for substantial changes.
- Explain the user need and the proposed improvement.
- Keep examples generic and fictional. Do not submit student records, private institutional documents, or personal data.
- Do not use a university’s name, logo, or claim its endorsement without written permission.

## Good first contributions

- Review keyboard navigation and focus visibility in the prototype.
- Suggest clearer event-card content and empty states.
- Add a translation while preserving meaning and accessibility.
- Document an event-discovery or participation-recognition pattern.
- Report a reproducible visual or interaction issue with browser and viewport details.

## Pull requests

1. Keep each pull request focused on one change.
2. Describe the problem, the change, and how a reviewer can inspect it.
3. For visual changes, include before/after screenshots using fictional content only.
4. Check that the page remains usable on a narrow mobile viewport and with a keyboard.
5. Do not add tracking, external scripts, or dependencies without discussion in an issue.

Maintainers should review for accessibility, privacy, clarity, and fit with the project principles. A contribution is not considered accepted until it is merged.

# CampusKit — Open UX patterns for campus engagement

CampusKit is an open-source starter project for making university events and extracurricular activities easier to discover, attend, and document.

It combines a small, accessible web prototype with reusable UX patterns and implementation notes. The project is designed for students, educators, and contributors who want to improve campus engagement tools.

> **Project status:** Early concept and prototype. This repository is independent and is not an official product of New Bulgarian University or any other institution. It uses fictional demo events and points. Institutional names, branding, student data, systems, or materials must not be added without permission.

## Why this project

University activities can be spread across calendars, social media, and separate registration forms. Students may struggle to find relevant events or understand how participation is recorded. CampusKit explores a clearer flow:

1. Discover activities in one place.
2. Understand the format, date, location, and accessibility details.
3. Save or register for an activity.
4. See participation and any associated recognition in a transparent way.

## What is included

- `index.html` — a responsive, browser-ready prototype with fictional events and sample participation points.
- `CONTRIBUTING.md` — contribution ideas and a lightweight review process.
- `LICENSE` — MIT License.

The prototype is a design exploration. It has no backend, account system, registration service, or connection to a university platform. Actions run locally in the browser only.

## Run the prototype

Open `index.html` in a modern browser. No build tools or dependencies are required.

## Principles

- **Clarity:** explain what an activity is, who it is for, and what happens next.
- **Accessibility:** use semantic HTML, keyboard-operable controls, visible focus, and readable contrast.
- **Privacy:** collect as little student data as possible; never place real personal data in demo issues or pull requests.
- **Transparency:** make participation rules and any recognition understandable.
- **Interoperability:** prefer documented, portable patterns over institution-specific assumptions.
